# Healthcare Platform - Database Schema & ER Model Documentation

## Entity Relationship Overview
The database is structured to support relational integrity, concurrency protection, multi-tenant role segregation, and clinical audit logging across PostgreSQL and SQLite environments.

---

### Core Tables & Specifications

#### 1. `users`
Stores authenticated identities across all roles (`patient`, `doctor`, `admin`).
* `id` VARCHAR(64) PRIMARY KEY
* `name` VARCHAR(255) NOT NULL
* `email` VARCHAR(255) UNIQUE NOT NULL
* `password` VARCHAR(255) NOT NULL (Argon2 / bcrypt hash)
* `role` VARCHAR(32) NOT NULL (`patient` | `doctor` | `admin`)
* `status` VARCHAR(32) DEFAULT 'PENDING_VERIFICATION' (`PENDING_VERIFICATION` | `ACTIVE` | `SUSPENDED`)
* `is_verified` BOOLEAN DEFAULT 0
* `verification_code` VARCHAR(64) NULL (Hashed 6-digit OTP)
* `totp_secret` VARCHAR(255) NULL (Encrypted at rest)
* `totp_enabled` BOOLEAN DEFAULT 0
* `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP

#### 2. `doctors`
Doctor professional profile, consultation configuration, and specialization.
* `id` VARCHAR(64) PRIMARY KEY
* `user_id` VARCHAR(64) UNIQUE NOT NULL (FK -> `users.id`)
* `specialisation` VARCHAR(128) NOT NULL
* `working_hours_start` VARCHAR(16) DEFAULT '09:00'
* `working_hours_end` VARCHAR(16) DEFAULT '17:00'
* `slot_duration_minutes` INTEGER DEFAULT 30
* `working_days` TEXT DEFAULT 'Monday,Tuesday,Wednesday,Thursday,Friday'

#### 3. `appointments`
Core scheduling table enforcing database-level double-booking protection.
* `id` VARCHAR(64) PRIMARY KEY
* `patient_id` VARCHAR(64) NOT NULL (FK -> `users.id`)
* `doctor_id` VARCHAR(64) NOT NULL (FK -> `doctors.id`)
* `date` VARCHAR(32) NOT NULL (YYYY-MM-DD)
* `start_time` VARCHAR(16) NOT NULL (HH:MM)
* `end_time` VARCHAR(16) NOT NULL (HH:MM)
* `status` VARCHAR(32) DEFAULT 'booked' (`booked` | `rescheduled` | `cancelled` | `completed` | `no_show`)
* `calendar_event_id` VARCHAR(255) NULL
* `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP
* **Constraint:** `UNIQUE(doctor_id, date, start_time)`

#### 4. `symptom_forms`
Stores patient-reported symptoms prior to pre-visit clinical triage.
* `id` VARCHAR(64) PRIMARY KEY
* `appointment_id` VARCHAR(64) UNIQUE NOT NULL (FK -> `appointments.id`)
* `symptoms` TEXT NOT NULL
* `duration` VARCHAR(64)
* `severity` INTEGER DEFAULT 5 (Scale 1-10)
* `medical_history` TEXT

#### 5. `pre_visit_summaries`
Stores structured clinical triage output generated by Ollama / Gemini / Clinical NLP engine.
* `id` VARCHAR(64) PRIMARY KEY
* `appointment_id` VARCHAR(64) UNIQUE NOT NULL (FK -> `appointments.id`)
* `urgency_level` VARCHAR(32) NOT NULL (`Low` | `Medium` | `High` | `Critical`)
* `chief_complaint` TEXT NOT NULL
* `suggested_questions` TEXT NOT NULL (JSON-serialized array + extended care metadata)
* `raw_llm_output` TEXT
* `status` VARCHAR(32) DEFAULT 'success'

#### 6. `consultations` & `prescriptions`
Authoritative clinical documentation and medication orders entered by consulting doctors.
* `consultations.id` VARCHAR(64) PRIMARY KEY
* `consultations.appointment_id` VARCHAR(64) UNIQUE NOT NULL (FK -> `appointments.id`)
* `consultations.doctor_id` VARCHAR(64) NOT NULL
* `consultations.patient_id` VARCHAR(64) NOT NULL
* `consultations.clinical_notes` TEXT NOT NULL
* `consultations.diagnosis` VARCHAR(255)
* `consultations.vitals` TEXT (JSON: BP, Pulse, Temp, SpO2)
* `prescriptions.id` VARCHAR(64) PRIMARY KEY
* `prescriptions.consultation_id` VARCHAR(64) NOT NULL (FK -> `consultations.id`)
* `prescriptions.medication_name` VARCHAR(255) NOT NULL
* `prescriptions.dosage` VARCHAR(128) NOT NULL
* `prescriptions.frequency` VARCHAR(128) NOT NULL
* `prescriptions.duration` VARCHAR(128) NOT NULL

#### 7. `post_visit_summaries`
Patient-friendly conversion of clinical notes with medication schedules and recovery instructions.
* `id` VARCHAR(64) PRIMARY KEY
* `consultation_id` VARCHAR(64) UNIQUE NOT NULL (FK -> `consultations.id`)
* `patient_friendly_summary` TEXT NOT NULL
* `medication_schedule` TEXT NOT NULL (JSON)
* `follow_up_steps` TEXT NOT NULL (JSON)

#### 8. `leave_days` & `leave_requests`
Doctor schedule blocks and approval workflows.
* `leave_requests.id` VARCHAR(64) PRIMARY KEY
* `leave_requests.doctor_id` VARCHAR(64) NOT NULL
* `leave_requests.from_date` VARCHAR(32) NOT NULL
* `leave_requests.to_date` VARCHAR(32) NOT NULL
* `leave_requests.reason` TEXT
* `leave_requests.status` VARCHAR(32) DEFAULT 'pending' (`pending` | `approved` | `rejected`)
* `leave_days.id` VARCHAR(64) PRIMARY KEY
* `leave_days.doctor_id` VARCHAR(64) NOT NULL
* `leave_days.leave_date` VARCHAR(32) NOT NULL

#### 9. `audit_logs` & `email_logs`
Tracks security events, MFA verification, cancellations, and asynchronous notification delivery.
* `audit_logs.id` VARCHAR(64) PRIMARY KEY
* `audit_logs.user_id` VARCHAR(64) NULL
* `audit_logs.action` VARCHAR(64) NOT NULL (`LOGIN_SUCCESS`, `MFA_CHALLENGE`, `BOOKING_CREATED`, `LEAVE_APPROVED`)
* `audit_logs.resource_type` VARCHAR(64)
* `audit_logs.resource_id` VARCHAR(64)
* `audit_logs.created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP
